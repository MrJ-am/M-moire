#+title: Tests de navigateur

Depuis ~docs/~ :

#+begin_src sh
npm run build:main
npm run test:e2e:install
npm run test:e2e
#+end_src

Playwright lance le service Node.js au port 4173 sous ~/matheval/~, avec une base PostgreSQL de test définie par ~BROWSER_DATABASE_URL~ (nom terminé par ~_test~). Les dépendances du service dans ~server/~ doivent être installées. Le workflow contrôle Firefox, Chromium sur ordinateur et Chromium avec écran portrait et événements tactiles. Les échecs conservent capture, vidéo et trace dans ~test-results/~ ; ce dossier est disponible pendant sept jours dans les artefacts GitHub du contrôle. Une erreur empêche la publication.

Les tests navigateur sont obligatoires aussi pour une modification des seules données. Dans ce cas, les données sont copiées dans le site sans recompiler Elm. Après le déploiement, ~check-published-site.py~ compare les pages, les scripts, les styles et les données servis en HTTPS aux empreintes des fichiers qui ont passé les tests. Un fichier absent ou une ancienne version fait échouer le contrôle de publication. Les erreurs 404 et les versions mélangées sont couvertes par ~python3 -m unittest discover -s docs/tests -p 'test_published_site.py'~ depuis la racine du dépôt.

| Fichier | Parcours vérifié |
| ~survey.spec.js~ | Clavier, animations réduites, coordonnées indépendantes, révisions, export et disposition des petits écrans |
| ~survey-gestures.spec.js~ | Souris, animations actives, tutoriel puis session entière sans saut de question, coordonnées conservées au centre, maintien d’une bille surélevée sous le pointeur, synchronisation de la note |
| ~survey.touch.spec.js~ | Gestes tactiles Chromium : tutoriel, glissement horizontal, défilement vertical, annulation de geste, ouverture d’une rédaction et navigation |

Les gestes tactiles sont injectés avec ~Input.dispatchTouchEvent~ : ils passent par le traitement des pointeurs et du défilement du navigateur. Réduire seulement la taille de la fenêtre ne simule pas ces gestes. Les tests attendent la fin des animations de lecture avant de saisir une bille ; ils inspectent aussi sa position *pendant* le glissement. Le parcours complet compare les réponses exportées aux notes et coordonnées observées dans l’interface.

Le contrôle de présentation couvre les largeurs 390, 820 et 1363 pixels : vignettes au-dessus des contrôles, panneau des curseurs compact lorsqu’il est au-dessus de la scène, hauteur commune lorsqu’ils sont côte à côte, scène sans cadre et numéro centré dans une bille proportionnée à sa taille. Il conserve une capture de chaque disposition, puis vérifie la réouverture d’une vignette et le passage à la suivante.

La régression signalée par ~431097.mp4~ est couverte par des prises décentrées et des trajectoires diagonales qui sortent de la barre, en portrait et sur un petit écran paysage, ainsi que par un départ vertical suivi d’un mouvement horizontal. Une saisie sur la bille ou la barre doit conserver le pointeur jusqu’au relâchement ; le défilement vertical de la page est essayé depuis les espaces libres. Une trajectoire parfaitement horizontale ne suffit pas à vérifier cette distinction.

Les autres tests portent sur le prototype conservé à ~prototype.html~. Pour cibler un contrôle : ~npm run test:e2e -- --project=chromium~ ou ~--project=chromium-touch~. Une émulation tactile ne remplace pas une vérification complémentaire sur un téléphone physique.

Sur Guix seulement, ~npm run test:e2e:guix~ applique le correctif Firefox avant les tests. La commande standard ~test:e2e~ n’applique pas ce correctif.

Le contrôle des portées injecte la paire R17-6/R17-7 issue de la banque générée, parcourt le tutoriel, ouvre les deux rédactions puis la comparaison. Il vérifie le contenu exact, les retraits de deux profondeurs, la sortie de portée, le rendu KaTeX et l’absence de débordement aux largeurs 390 et 1363 pixels. Des captures sont conservées dans les résultats du test. Les deux membres ne diffèrent que par les espaces initiaux, ce que les tests du compilateur vérifient également.
