#+title: Mémoire et instrument scientifique

Ce dépôt conserve les manuscrits, la bibliographie, les sources scientifiques
du questionnaire, leurs artefacts et la documentation du mémoire. Le code
applicatif en développement est désormais dans [[https://github.com/MrJ-am/matheval][Mateval]]. Le serveur n’est
plus un composant de ce dépôt ; son assemblage relève de mrjam-plateforme
et son exploitation de vps-infrastructure.

* Séparation de l’application

L’extraction prend pour référence le commit
=2afce3aae14af13ef6dbda960cf5a4716924dc72=. L’historique antérieur est conservé.
Les backends historiques, leur manifeste et leurs lanceurs de déploiement
sont retirés de la branche courante après vérification de la publication de
Mateval. Aucun service ni aucune base de production n’est modifié par cette
séparation de dépôts.

Les fichiers scientifiques de =research/=, la bibliographie de =bib/=,
les manuscrits Org, les archives et les documents ambigus conservent leurs
chemins et leurs octets. Ce nettoyage technique ne relit et ne réécrit pas
leur contenu. Les anciens documents d’exploitation conservés sont des
références historiques, sans valeur d’autorisation de déploiement.

* Instrument figé pour la reproductibilité

=docs/= est conservé comme instrument scientifique de cette édition du
mémoire. Il ne constitue pas une deuxième branche de développement de
l’application. Il ne doit pas être sélectionné pour créer l’environnement
Codex du VPS. Les évolutions de produit, du serveur et de son interface
s’effectuent dans Mateval.

Cette conservation évite de rompre les dépendances du travail scientifique :
=build-bank.py= lit les sources Org et produit notamment les banques JSON ;
=validate-bank.cjs= compare ces banques et vérifie aussi les pages et leurs
ressources. Les tests du générateur, les ressources typographiques, les
artefacts du questionnaire et les ressources de démonstration restent à
leur emplacement. Le découplage de cet outillage sera un travail explicite
du mémoire, pas un effet indirect d’une refonte du serveur.

Une seule adaptation de point d’entrée accompagne l’extraction : le proxy
Vite historique =/matheval/api= vise désormais le monolithe Rust local sur
=127.0.0.1:38101= au lieu de l’ancien serveur Node sur le port 3000.
Cela ne rend pas opérationnels l’administration, l’import SQL ou les parcours
de collecte : ils restent soumis à qualification dans Mateval. Les commandes
de compilation et de test conservées ne lancent aucun backend Node ou Lisp.
Les tests de navigateur supposent un harnais local explicitement synthétique.
Ils n’ont pas été exécutés contre des réponses ou une base réelles pendant
cette séparation.

* Publication du questionnaire

Mateval embarque une copie de distribution de la projection publique
=docs/site/data/bank.json=, version 0.3.0, et la verrouille par révision,
blob Git et SHA-256. Cette projection contient les questions et les rédactions
proposées à l’évaluation, sans les réponses collectées des participants.
Sa copie dans Mateval ne déplace ni les sources du questionnaire ni les
artefacts nécessaires au mémoire.

Le verrou et la cartographie de l’extraction se trouvent dans Mateval :
[[https://github.com/MrJ-am/matheval/blob/main/frontend/artifacts.lock.json][provenance de l’artefact]] et
[[https://github.com/MrJ-am/matheval/blob/main/docs/memoire-cleanup.json][manifeste de conservation et de nettoyage]].
Une nouvelle édition scientifique produit une nouvelle publication explicite ;
elle ne déclenche aucun import serveur ni déploiement automatique.
