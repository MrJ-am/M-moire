#+title: Regards — rédactions mathématiques

* Le site

Regards propose aux enseignants de lire et noter des rédactions, puis de les situer sur trois axes indépendants : Confus–Lisible, Vague–Précis et Fautif–Valide. Le parcours comprend une aide initiale facultative, des aides contextuelles déclenchées une seule fois et réinitialisables, une lecture progressive, trois barres à billes numérotées et une vue libre en trois dimensions.

La note va de 0 à 3 par quarts de point. Chaque coordonnée va de −10 à +10 en interne ; les axes affichent seulement le repère du milieu. Le zéro correspond à un attendu contextualisé. Les réponses sont sauvegardées progressivement dans PostgreSQL par le service de collecte. Une copie locale permet la reprise dans le même navigateur et les retransmissions après une interruption réseau. La validation finale confirme leur réception.

* Développer et vérifier

Utiliser [[https://github.com/MrJ-am/vps-infrastructure/blob/main/assemblage/DEVELOPPEMENT.md][les commandes locales centrales]] : frontend Elm/elm-ui/elm-animator,
elm-review obligatoire, données/correcteur et parcours navigateur selon impact.
Backend Common Lisp qualifié avec vrai PostgreSQL isolé. ASDF incrémental dans
l’image persistante commune cl-mcp/Tron ; validation finale propre. Pas de backend
Node pour l’aperçu cible ni de campagneCI de développement. server/ reste la
référence différentielle temporaire sur une base de test indépendante.
Les scripts de ce composant restent appelés centralement, versions verrouillées.

Éditer uniquement les textes et tableaux dans [[file:research/questions.org][questions.org]], et les définitions dans [[file:research/contrats.org][contrats.org]]. Après modification, ~npm run build:data~ produit les JSON, l’audit, les effectifs et les renvois des contrats aux rédactions. Les blocs générés sont balisés. ~npm run dev~ régénère les données avant d’ouvrir l’aperçu.

~npm run check:data~ reconstruit les sorties en mémoire, vérifie les liens relatifs et les pages PDF, et échoue si un fichier généré diverge. Ce contrôle local bloquant précède toute reconstruction : une correction manuelle du JSON ne peut donc pas masquer une source Org restée ancienne. Les erreurs de structure, de code, de cellule ou d’appariement bloquent la génération. Les identifiants de question et rédaction doivent rester stables au sein d’une version ; un changement de corpus exige une nouvelle version pour l’analyse des exports.

* Collecte et administration

La collecte conserve la version de banque, les niveaux, la graine et les ordres de présentation, les notes initiales et révisées, les coordonnées et leurs axes évalués, les questions passées et un journal horodaté des interactions. Les préférences d’aide restent locales au navigateur et ne sont pas transmises à la collecte. Une coordonnée à zéro dont l’axe n’est pas dans ~evaluatedAxes~ représente une absence de jugement, pas une réponse zéro.

Le détail des choix méthodologiques et des limites de collecte se trouve dans ~research/protocole.org~.

* Format éditorial Org

Les propriétés ~CUSTOM_ID~, ~NIVEAU~, ~DOMAINE~ et ~FAMILLE~ identifient les questions. ~CIBLES~ porte les liens vers les contrats et contrôles ; les cellules du tableau nommé ~contrats-Rxx~ portent seules le codage (respecté, non respecté, discutable ou non pertinent). Les définitions sont dans le référentiel, les analyses dans les rédactions. Les tags servent au filtrage et ne remplacent pas ces propriétés.

Les blocs ~verse~ conservent exactement les espaces et les retours à la ligne. Le sous-ensemble accepté est décrit par la structure de [[file:research/questions.org][questions.org]] : titres, propriétés explicites, tableaux, blocs verse et paragraphes d’analyse. Le compilateur n’exécute aucun code Babel et refuse les structures de données inattendues. Dans les textes publics, le rendu prend en charge les paragraphes, lignes, listes simples, gras Markdown et formules LaTeX déjà utilisés par le site ; il ne réalise pas un export général d’Org.

Les ancres inter-fichiers utilisent ~CUSTOM_ID~ ; les liens PDF paginés utilisent ~docview~. Ces syntaxes sont décrites dans les [[https://orgmode.org/manual/External-Links.html][liens externes du manuel Org]]. Le lien ordinaire portant le titre d’une source reste utilisable avec un autre lecteur de PDF.
